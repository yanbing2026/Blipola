# Kindergarten Classroom Integration

Blipola is a reusable learning layer for the Kindergarten Classroom app. The host keeps ownership of question content, answer validation, UI, accounts, and navigation; Blipola adds learning context, adaptive recommendations, hints, review timing, and Buddy events.

## v0.5 adapter

Use `js/kindergarten-adapter.js` when the host question object follows the Kindergarten Classroom shape:

```js
import { createKindergartenIntegration } from "./kindergarten-adapter.js";

const integration = createKindergartenIntegration({
  progress: blipolaProgress,
  classroomProgress: hostProgress,
  onHostActivity: activity => {
    // Optional: persist the event into the host activity log.
  }
});

const context = integration.start(question);

const hint = integration.hint(context);

const result = integration.complete(context, selectedChoiceId, attemptCount);
```

### Host question → Blipola

The adapter maps:

- `question.sourceKey` / `question.key` → skill
- `question.sourceLevel` / `question.level` → level
- `question.itemId` → learning item
- `question.promptText` / `question.speakText` → question text
- `question.promptHTML` → visual prompt
- `question.choices[].id` → answer choices
- `question.lang` → language
- `question.mode` → question mode

For questions generated by Kindergarten Classroom, `itemId` is the authoritative answer identifier. This is important for science, patterns, comparing, positions, time, money, and other questions where the displayed answer is not always the item's primary ID.

### Blipola → Host

`integration.complete()` returns the normal Blipola result and emits a compact host activity record:

```js
{
  key,
  level,
  item,
  selected,
  correct,
  firstTry,
  attempts,
  at
}
```

The host may store this record in its existing activity log. Blipola does not require the host to expose child account credentials or private profile data.

## Ownership boundary

### Kindergarten Classroom owns

- question generation/content;
- answer selection and UI;
- account/profile boundaries;
- navigation;
- child-facing content;
- existing rewards and presentation.

### Blipola owns

- learning context;
- recommendation;
- hint progression;
- mastery evidence;
- review timing;
- Daily Adventure;
- Buddy state/events.

The AI provider boundary remains the same: a future LLM may generate hints, explanations, practice, or parent summaries, but it must not control scoring, mastery, progression, review timing, or safety decisions.

## Backward-compatible progress seeding

`seedBlipolaProgressFromClassroom()` can initialize Blipola's local learning evidence from the host's `activityLog`. This is intentionally conservative: it seeds evidence without replacing the host's existing progress schema.

## Integration principle

Do not rewrite the Kindergarten Classroom question engine just to add Blipola. Add a thin adapter at the boundary, then let Blipola observe and enrich the existing learning flow.
